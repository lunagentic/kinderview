# 07. 이슈(Issue) 스펙

## 7.1 목적

업무 진행 과정에서 발생하는 **문제와 블로커**를 관리한다.

업무 상태와 이슈 상태는 **분리**한다. (원칙 6)
업무는 "어디까지 진행됐는가", 이슈는 "무엇이 막고 있는가"를 답한다.

| | 업무 상태 | 이슈 상태 |
|---|---|---|
| 질문 | 어디까지 진행됐나 | 무엇이 막고 있나 |
| 값 | 대기/진행중/검토/완료 | Open/확인중/해결 |
| 관계 | 이슈가 있어도 업무는 진행중일 수 있다 | 이슈 해결이 업무 완료를 뜻하지 않는다 |
| 자동 전이 | 없음 | 없음 |

## 7.2 입력 항목

| 항목 | 필수 | 컨트롤 | 비고 |
|---|---|---|---|
| 이슈명 | ✔ | 텍스트 | 1~120자 |
| 관련 프로젝트 | ✔ | 셀렉트 | |
| 관련 업무 | | 검색 셀렉트 | 선택한 프로젝트의 업무로 한정 |
| 내용 | ✔ | 텍스트영역 | 상황과 원인 |
| 담당자 | ✔ | Slack 멤버 검색 | 이슈 해결 책임자 |
| 중요도 | | 셀렉트 | 높음 / 보통 / 낮음. 기본 `보통` |
| 해결 목표일 | | 날짜 | |
| 영향 | | 텍스트 | 예: 콘텐츠 등록 일정 3일 지연 예상 |
| 상태 | | 셀렉트 | 기본 `Open` |

- **관련 업무는 선택**이다. 특정 업무에 귀속되지 않는 프로젝트 차원 이슈가 있다.
- 업무 상세에서 `+ 이슈 등록`으로 진입하면 프로젝트·업무가 자동으로 채워진다.

## 7.3 상태

```
Open → 확인중(CHECKING) → 해결(RESOLVED)
```

- 모든 방향 전이를 허용한다. (재발 시 해결 → Open)
- `해결` 처리 시 `resolved_at`을 기록한다.
- 이슈 상태 변경은 **연결된 업무의 상태를 바꾸지 않는다.**

### 업무에 미치는 영향

| 이슈 상태 | 연결 업무 표시 |
|---|---|
| `OPEN`, `CHECKING` | 🔥 이슈 있음 플래그 |
| `RESOLVED` | 플래그 해제 |

## 7.4 외주 관련 이슈

외주 관련 이슈도 **동일한 Issues에서** 관리한다. 별도 화면을 만들지 않는다.

```
외주 디자인 납품 지연
────────────────────────
관련 업무   활동지 디자인 제작
외주 업체   OO 디자인        ← 연결된 업무에서 자동 표시
내부 담당   @김OO
중요도      높음
영향        콘텐츠 등록 일정 3일 지연 예상
```

- 외주 업체·외부 작업자는 이슈에 직접 입력하지 않는다. **연결된 업무에서 읽어와 표시**한다.
- 이슈 담당자는 내부 구성원이다.

## 7.5 Issues 목록

| 컬럼 | 내용 |
|---|---|
| 이슈명 | 이슈명 + 중요도 배지 |
| 프로젝트 | 프로젝트명 |
| 관련 업무 | 업무명 (없으면 `-`) |
| 담당 | 프로필 + 이름 |
| 중요도 | 높음(빨강) / 보통(회색) / 낮음(연회색) |
| 목표일 | 날짜. 초과 시 빨간색 |
| 상태 | Open / 확인중 / 해결 |

### 필터

`[전체] [내 담당 이슈] [Open] [확인중] [해결] [중요도 높음]`

- 기본 진입 시 **미해결(Open + 확인중)** 만 표시한다.
- 정렬: 중요도 내림차순 → 해결 목표일 오름차순 → 등록일.

## 7.6 이슈 등록 시 알림

| 조건 | 대상 |
|---|---|
| 이슈 등록 | 이슈 담당자 DM |
| 중요도 `높음` 이슈 등록 | 이슈 담당자 DM + 프로젝트 채널 |
| 관련 업무가 있는 경우 | 해당 업무의 담당자 DM (이슈 담당자와 다를 때) |
| 해결 목표일 초과 | 이슈 담당자 DM (매일 09:30) |
| 이슈 해결 | 등록자 DM |
