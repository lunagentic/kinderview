# 01. 서비스 개요 및 원칙

## 1.1 서비스 정의

**KinderFlow** — 프로젝트의 업무와 담당을 명확히 정의하고, 내부 업무와 외주 작업의
진행·이슈를 추적하여 전체 업무 흐름을 한눈에 보여주는 프로젝트·업무 관리 도구.

## 1.2 해결하려는 문제

| 문제 | KinderFlow의 대응 |
|---|---|
| 업무가 Slack·문서·개인 메모에 흩어져 전체 진행을 알 수 없다 | 업무를 프로젝트에 연결해 한곳에 기록한다 |
| "이건 누가 하고 있죠?"가 반복된다 | 업무마다 담당자를 1명 원칙으로 명시한다 |
| 외주 진행 상황이 담당자 머릿속에만 있다 | 외주를 동일한 Task 구조로 관리하고 함께 집계한다 |
| 진행 상황 보고를 위해 매주 별도 취합 작업이 필요하다 | 기록된 업무·이슈에서 Weekly Report를 자동 생성한다 |
| 문제(블로커)와 업무 진행 상태가 뒤섞여 관리된다 | 업무 상태와 이슈를 분리해 각각 추적한다 |

## 1.3 핵심 원칙

1. 업무를 **배정**하는 시스템이 아니라 업무의 **담당을 명확히 정의**한다.
2. 프로젝트와 개인 업무가 연결되어야 한다.
3. 사업관리·기획·개발·마케팅·운영·외주 작업을 구분한다.
4. 내부 담당자는 Slack을 기준으로 한다. (별도 구성원 DB를 만들지 않는다)
5. 외주 작업은 외부 작업자와 내부 담당자를 함께 관리한다.
6. 업무 상태와 이슈 상태를 분리한다.
7. 개별 업무를 관리하면 전체 현황이 자동으로 집계된다.
8. 별도 보고 작업 없이 Weekly Report가 생성되어야 한다.

### 원칙이 설계에 반영되는 지점

| 원칙 | 설계 반영 |
|---|---|
| 1, 담당 정의 | `task.owner`는 **필수**이자 **단일 값**. 다인 담당은 협업자로 표현한다 |
| 2, 연결 | `task.project_id` 필수. 프로젝트 없는 업무는 만들 수 없다 |
| 4, Slack 기준 | 구성원 테이블은 Slack User ID를 PK로 하는 **캐시**. 자체 가입/회원 관리 없음 |
| 5, 외주 | 외주는 별도 메뉴가 아니라 업무 영역 값. 상세 정보만 1:1 확장 |
| 6, 분리 | `task.status`와 `issue.status`는 서로 전이시키지 않는다. 이슈는 업무의 **플래그**로만 표시 |
| 7, 자동 집계 | 진행률·현황은 저장하지 않고 업무 데이터에서 **계산**한다 |
| 8, 무보고 | Weekly Report는 사람이 입력하는 필드 없이 생성 가능해야 한다 |

## 1.4 사용자

| 사용자 | 주 사용 목적 | 주 사용 화면 |
|---|---|---|
| 팀 구성원 (담당자) | 내 담당 업무 확인, 상태 갱신, 이슈 등록 | Tasks(내 담당 업무), 업무 상세 |
| 프로젝트 리드 | 프로젝트 진행·지연·이슈 확인 | Overview, Tasks(프로젝트 필터), Issues |
| PO / 사업 총괄 | 전체 현황 파악, 주간 보고 | Overview, Weekly |
| 외주 관리 담당 | 외주 진행·납품·검수 관리 | Tasks(외주 필터), Issues |

> 외부 외주 업체·작업자는 **KinderFlow 사용자가 아니다.** 내부 담당자가 대신 기록한다.

## 1.5 MVP 범위

### 포함

- 프로젝트 생성/관리
- 업무 등록·수정·상태 관리 (내부 업무 / 외주 작업)
- 업무 영역 분류, 담당자·협업자 정의
- Slack 구성원 동기화
- 지연 자동 표시
- Overview (프로젝트별 / 업무 영역별 / 담당자별 현황)
- Issues 등록·해결 관리
- Weekly Report 자동 생성 및 Slack 공유
- Slack 알림 (담당 등록, 마감, 지연, 검토, 이슈, 외주 납품)

### 비범위 (MVP 이후 논의)

| 항목 | 사유 |
|---|---|
| 세분화된 권한/역할 관리 | 소규모 내부 팀 전제. 전원 조회·편집 가능으로 시작 |
| 간트차트 / 타임라인 뷰 | 일정 관리는 Google Calendar 역할 |
| 공수 입력·타임트래킹 | 관리 비용이 기록 부담을 넘어선다 |
| 업무 댓글 / 파일 첨부 | 논의는 Slack, 문서는 Drive/Notion |
| 하위 업무(Subtask), 반복 업무 | 구조 복잡도 대비 MVP 효용 낮음 |
| 결재/승인 워크플로 | 검수 상태로 최소 대응 |
| 외부 업체 계정 로그인 | 외주는 내부 담당자가 대리 기록 |
| 예산·정산 관리 | 별도 도구 영역 |

## 1.6 성공 기준 (MVP 종료 시점 판단)

| 지표 | 목표 |
|---|---|
| 주간 업무 기록률 | 팀 구성원의 실제 업무 중 80% 이상이 Task로 등록 |
| 상태 최신성 | 진행중 업무의 90% 이상이 최근 7일 내 상태 갱신 |
| 주간 보고 준비 시간 | 기존 대비 50% 이상 단축 (Weekly Report 그대로 공유 가능) |
| 담당 명확성 | 담당자 미지정 업무 0건 (필수값으로 강제) |
| 이슈 추적 | Open 이슈의 평균 해결 소요일 측정 가능 |

## 1.7 서비스별 역할 분담

```
                    KinderFlow
             프로젝트·업무 기준 데이터
                       │
        ┌──────────────┼──────────────┐
        ▼              ▼              ▼
      Slack      Google Calendar   Google Tasks
   구성원·알림        일정·마감       개인 할 일
```

KinderFlow는 Slack이나 Google의 기능을 **대체하지 않는다.**

- Slack — 구성원 정보의 원천(Source of Truth), 알림 채널
- Google Calendar — 일정·마감의 캘린더 표현 (Phase 4)
- Google Tasks — 개인 단위 할 일 (Phase 4)
