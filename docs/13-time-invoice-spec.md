# 13. 타임트래킹 · 인보이싱 스펙

> 2026-09-05 추가. 레퍼런스(설계사무소용 프로젝트 관리 도구)의 세 기능 구성을 가져오면서,
> KinderFlow 의 실제 업무 방식에 맞게 다시 정의했다.

## 13.1 메뉴 재편

```
KinderFlow
├─ 프로젝트 매니징   현황 · 업무 · 타임라인 · 이슈 · 주간 리포트
├─ 타임트래킹        내 타임시트 · 투입 집계 · 경비
└─ 인보이싱          외주 지급 · 프로젝트 경비
                     (알림함은 상단 우측 보조 메뉴)
```

기존 Overview·Tasks·Issues·Weekly 는 **프로젝트 매니징** 아래 2차 탭으로 들어갔다.
예전 주소(`#/tasks` 등)는 새 주소로 자동 전환된다.

## 13.2 타임트래킹

### 왜 넣었나, 그리고 무엇을 경계하나

기획서 §1.5 는 **공수 입력·타임트래킹을 비범위로 명시**했다.
"관리 비용이 기록 부담을 넘어선다"는 이유였고, 그 판단은 여전히 유효하다.
그래서 **시간 기록을 업무 등록의 조건으로 만들지 않는다.**

- 시간을 적지 않아도 업무·진행·리포트는 전부 그대로 동작한다
- 시간은 **주간 격자에 숫자만 넣는 방식**으로 받는다. 타이머·시작/정지 버튼을 두지 않는다
- 시간 기록 여부를 알림으로 독촉하지 않는다

### 데이터

`time_entry` — **하루·한 업무·한 사람당 한 줄**(UNIQUE). 격자 입력이 곧 upsert 다.

| 필드 | 설명 |
|---|---|
| `task_id` | 어떤 업무에 |
| `slack_user_id` | 누가 |
| `work_date` | 어느 날 |
| `hours` | 몇 시간 (0 초과 24 이하) |

- 값을 비우면 행이 삭제된다. "0시간"을 저장하지 않는다
- 담당자가 아니어도 기록할 수 있다 — 협업자도 시간을 쓴다

### 화면

```
타임트래킹                          [◀ 지난주] [다음주 ▶]
8/31 ~ 9/6 · 이번 주 20.5시간
──────────────────────────────────────────────────────
업무                  월   화   수   목   금  토  일  합계
관찰 기록 API 개발          6   7   5.5           18.5
데이터 마이그레이션 검증          2                  2
──────────────────────────────────────────────────────
일별 합계                   6   7   7.5          20.5
```

- 오늘 열은 배경으로 구분한다
- `업무 추가` 로 내 영역 업무를 격자에 올린다
- 아래에 **이번 주 투입**(프로젝트별 · 구성원별)을 진행률 바로 보여준다

## 13.2.1 경비

> 2026-09-05 추가. 요율·인건비는 **넣지 않기로 확정**하고 실비만 받는다.

프로젝트에 쌓이는 돈에는 두 종류가 있다. **외주 지급**(§13.3)과 **실비**다.
교통비·인쇄비·구독료처럼 사람이 먼저 쓰고 나중에 정산하는 돈은
지금까지 어디에도 남지 않았다 — 그래서 `expense` 를 하나 더 뒀다.

### 데이터

`expense` — 한 건이 한 줄이다. 업무에 연결해도 되고, 프로젝트에만 달아도 된다.

| 필드 | 설명 |
|---|---|
| `project_id` | 어느 프로젝트에 (필수) |
| `task_id` | 어느 업무에 (선택) |
| `slack_user_id` | 누가 썼나 |
| `spent_on` | 언제 |
| `category` | `TRANSPORT` 교통 · `MATERIAL` 자재·인쇄 · `MEAL` 식대 · `SOFTWARE` 소프트웨어 · `ETC` 기타 |
| `amount` | 금액(원, 0 초과) |
| `memo` | 무엇에 썼나 |

### 규칙

- 금액은 **0보다 커야 한다.** 마이너스 정산은 별도 건으로 적는다
- 승인 절차를 두지 않는다. 소규모 팀에서 결재 단계는 기록을 멈추게 한다
- 영수증 첨부는 넣지 않았다 — 파일 저장소가 필요해지고, MVP 범위를 넘는다

### 화면

경비는 **타임트래킹에서 등록**하고(같은 주 단위로 정산하므로),
**인보이싱에서 프로젝트별로 합산해 본다**(돈을 보는 화면이므로).

```
이번 주 경비
592,300원  12건
[교통 77,800원] [자재·인쇄 181,500원] [식대 150,000원] …
──────────────────────────────────────────────────────
사용일  프로젝트      분류   내용                지출자  금액
9/2   Kinderverse  교통   파일럿 어린이집 방문   김OO   18,400원
```

## 13.3 인보이싱

### 방향을 뒤집었다

레퍼런스의 인보이싱은 **고객에게 청구**하는 기능이다(시간 × 역할 요율 → 청구서).
킨더보드는 외부에 청구하는 조직이 아니라 자체 서비스 팀이고,
돈이 오가는 지점은 **외주 업체에 지급**하는 쪽이다.

그래서 방향을 뒤집어 **외주 지급 관리**로 만들었다.
내부 인건비를 시간 × 요율로 환산하는 기능은 넣지 않았다 —
급여를 역산할 수 있는 데이터를 도구에 넣는 선택은 별도 판단이 필요하다.

### 데이터

`outsourcing` 에 컬럼 3개를 더했다. 외주는 이미 업무와 1:1 이라 별도 표가 필요 없다.

| 필드 | 설명 |
|---|---|
| `amount` | 계약 금액(원). 비어 있어도 되고, 합계에서 제외된다 |
| `payment_status` | `PLANNED` 지급 예정 → `REQUESTED` 청구 접수 → `PAID` 지급 완료 |
| `paid_at` | 지급 완료 처리일 |

### 규칙

- **검수가 `승인`되지 않은 건은 지급 완료로 바꿀 수 없다.** 서버에서 막는다
- 금액이 비어 있는 건수를 화면 상단에 알린다 — 합계가 조용히 틀리지 않도록
- 지급 상태는 업무 상태·검수 상태와 **별개**다. 업무가 완료돼도 지급은 따로 관리한다

### 화면

```
인보이싱
지급 예정 7,400,000원(3건)  청구 접수 4,500,000원(1건)  지급 완료 0원(0건)  전체 11,900,000원
──────────────────────────────────────────────────────────────────
외주 업무          업체            프로젝트      납품 예정  검수    금액        지급
누리과정 연계표 제작  한빛 콘텐츠·김작가  콘텐츠 패키지   9/4     검수중  4,500,000  청구 접수
교사 워크북 인쇄     한빛 콘텐츠·박인쇄  콘텐츠 패키지   9/7     미검수  2,400,000  지급 예정
```

## 13.4 API

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/time/week?week=&member=` | 한 사람의 한 주 타임시트 |
| POST | `/api/time` | 시간 입력·수정·삭제 (`hours: 0` 이면 삭제) |
| GET | `/api/time/summary?from=&to=` | 기간 투입 집계 (프로젝트·영역·구성원별) |
| GET | `/api/payments?status=` | 외주 지급 목록 + 요약 |
| PATCH | `/api/payments/:taskId` | 금액·지급 상태 변경 |
| GET | `/api/expenses?from=&to=&project=&member=` | 경비 목록 + 요약(프로젝트·분류별) |
| POST | `/api/expenses` | 경비 등록 |
| DELETE | `/api/expenses/:id` | 경비 삭제 |

## 13.5 넣지 않은 것

| 안 넣은 것 | 이유 |
|---|---|
| 타이머(시작/정지) | 기록 부담을 키운다. 주간 격자로 충분하다 |
| 역할별 시간당 요율 | 급여 역산이 가능해진다. **넣지 않기로 확정**(2026-09-05) |
| 인건비 환산·프로젝트 원가 | 위와 같은 이유. 원가는 외주 지급 + 실비까지만 본다 |
| 경비 결재·승인 단계 | 소규모 팀에서 결재는 기록을 멈추게 한다 |
| 영수증 파일 첨부 | 파일 저장소가 필요해진다. MVP 범위 밖 |
| 고객 청구서 발행 | 킨더보드는 외부에 청구하는 조직이 아니다 |
| 회계 연동(Quickbooks 등) | 국내 회계 환경과 맞지 않는다 |
| 시간 기록 독촉 알림 | 기록을 강제하면 숫자만 채워지고 정확도는 떨어진다 |
