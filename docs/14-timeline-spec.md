# 14. 타임라인 (페이즈 · 간트 · 마일스톤) 스펙

> 2026-09-05 추가. 프로젝트 매니징에 "지금 무엇이 겹치고, 무엇이 언제까지인가"를
> 한 화면에서 볼 수단이 없었다. 업무 목록은 줄로 보여줄 뿐 기간을 보여주지 못한다.

## 14.1 세 가지를 넣었다

| 개념 | 무엇인가 | 왜 필요한가 |
|---|---|---|
| **페이즈**(phase) | 프로젝트 안의 기간 단위 (기획·설계 / 개발 / 검증·오픈) | 업무 20건을 한 줄로 볼 수 없다. 묶는 층이 하나 필요하다 |
| **간트**(타임라인 화면) | 페이즈 기간을 가로 막대로 그린 화면 | 프로젝트 간 겹침은 표로는 보이지 않는다 |
| **마일스톤**(milestone) | 날짜 하나로 표시되는 약속 (베타 오픈, 납품 마감) | 기간이 아니라 **한 점**인 약속은 막대로 표현되지 않는다 |

## 14.2 데이터

### phase

| 필드 | 설명 |
|---|---|
| `project_id` | 어느 프로젝트에 (필수) |
| `name` | 페이즈 이름 |
| `start_date` / `end_date` | 기간. **비워도 된다** |
| `sort_order` | 프로젝트 안에서의 순서 |

**기간을 비우면 소속 업무의 시작·마감에서 계산한다.** 계산 결과는 저장하지 않는다
(원칙 6·7 — 파생 값은 저장하지 않는다). 화면에서는 점선 테두리로 "계산된 기간"임을 알린다.

페이즈를 삭제해도 **업무는 남는다.** 연결만 끊긴다(`ON DELETE SET NULL`).

### milestone

| 필드 | 설명 |
|---|---|
| `project_id` | 어느 프로젝트에 (필수) |
| `phase_id` | 어느 페이즈에 (선택 — 프로젝트에 직접 달아도 된다) |
| `name` | 마일스톤 이름 |
| `due_date` | 날짜 (필수) |
| `done_at` | 달성 시각. 비어 있으면 미달성 |

상태는 저장하지 않고 계산한다.

| 상태 | 조건 | 표시 |
|---|---|---|
| 달성 | `done_at` 있음 | ✓ · 완료색 |
| 지연 | `done_at` 없고 `due_date < 오늘` | ! · 지연색 |
| 예정 | 그 밖 | 프로젝트 색 테두리 |

### task.phase_id

업무에 `phase_id` 를 하나 더했다. **선택 항목이다** — 지정하지 않은 업무는
타임라인에서 "페이즈 미지정 N건"으로만 세어진다. 페이즈를 쓰지 않아도 앱은 그대로 돌아간다.

## 14.3 화면

```
타임라인
[페이즈 기간 — 진한 부분이 완료 비율] [◇ 예정] [◆ 지연] [◆ 달성] [| 오늘]
                6월      7월      8월      9월      10월
● Kinderverse  6/7 ~ 10/10                      [+ 페이즈] [+ 마일스톤]
  기획·설계        ▓▓▓▓▓▓▓▓░░░░░░░  6/7 ~ 8/18
  업무 4 · 50%
  개발                      ░░░░░░░░░░  8/11 ~ 9/17
  업무 4 · 0%
  마일스톤 3          ◆        ◇      ◇
```

### 색을 쓰는 규칙

화면 전체와 같은 규칙을 따른다. 색이 하는 일은 셋뿐이다.

1. **프로젝트 정체성** — 막대 색. 프로젝트마다 고정이고, 필터로 목록이 줄어도 바뀌지 않는다
2. **진행률** — 같은 색의 **채움 길이**. 새 색을 만들지 않는다
3. **상태** — 마일스톤의 달성/지연에만. 지연 빨강은 예약된 색이라 다른 데 쓰지 않는다

막대 위에는 글자를 얹지 않는다. 진한 채움 위에서 읽히지 않기 때문이다.
페이즈 이름은 왼쪽 축이 달고, 막대 오른쪽에는 기간만 덧붙인다.
**색만으로 구분되는 곳은 없다** — 어디서든 이름이 함께 나온다.

### 프로젝트 색을 4칸으로 줄인 이유

6칸(indigo · orchid · teal · amber · purple · blue)일 때
보라 `#7A4FD4` 와 파랑 `#2E7DF6` 이 **정상 시야에서도 ΔE 13.3**(기준 15)로
구분되지 않았다. 색각 이상에서는 더 붙었다.

4칸으로 줄이고 각 칸을 다시 잡아 대비·색각 검증을 통과시켰다.

| 칸 | 라이트 | 다크 |
|---|---|---|
| `--p0` | `#3B2FC8` | `#6055DE` |
| `--p1` | `#CE5EC6` | `#C85FC0` |
| `--p2` | `#0E9384` | `#17A187` |
| `--p3` | `#C77B12` | `#C08722` |

배정 기준은 id 해시가 아니라 프로젝트의 `sort_order` 다.
등수가 아니라 프로젝트 자체가 가진 값이라, 프로젝트를 새로 만들어도
기존 프로젝트의 색이 바뀌지 않는다.

**바꾸려면 다시 검증할 것.** 눈으로 판단하지 않는다.

### 표로도 볼 수 있다

간트 아래에 `표로 보기`(접힘)와 **마일스톤 목록**이 있다.
색을 못 보는 환경, 인쇄, 스크린리더에서도 같은 내용을 읽을 수 있어야 한다.

## 14.4 API

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/timeline` | 프로젝트 × 페이즈 × 마일스톤을 기간과 함께 한 번에 |
| GET | `/api/phases?project=` | 페이즈 목록 (업무 수·완료 수 포함) |
| POST | `/api/phases` | 페이즈 추가 |
| PATCH | `/api/phases/:id` | 페이즈 수정 |
| DELETE | `/api/phases/:id` | 페이즈 삭제 (업무는 남는다) |
| GET | `/api/milestones?project=` | 마일스톤 목록 |
| POST | `/api/milestones` | 마일스톤 추가 |
| PATCH | `/api/milestones/:id` | 수정 · 달성 처리(`done: true`) |
| DELETE | `/api/milestones/:id` | 삭제 |

`GET /api/tasks` 에 `phase=` 필터가 추가됐다.

## 14.5 넣지 않은 것

| 안 넣은 것 | 이유 |
|---|---|
| 업무별 간트 막대 | 업무가 20건 넘으면 읽을 수 없는 화면이 된다. 페이즈까지가 읽히는 단위다 |
| 의존 관계(선행/후행 화살표) | 관계를 유지하는 비용이 얻는 것보다 크다. 소규모 팀에서는 페이즈 순서로 충분하다 |
| 드래그로 기간 조정 | 날짜는 폼에서 고친다. 드래그는 실수로 일정을 바꾸기 쉽다 |
| 임계 경로(critical path) 계산 | 의존 관계가 없으면 계산할 수 없다 |
| 리소스(인원) 배분 뷰 | 담당은 영역 리드로 이미 정해진다. 배분할 대상이 없다 |
