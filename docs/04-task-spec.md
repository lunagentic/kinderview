# 04. 업무(Task) 스펙

## 4.1 업무 등록

### 입력 항목

**기본 정보 (필수)**

| 항목 | 컨트롤 | 검증 |
|---|---|---|
| 업무명 | 텍스트 | 1~120자 |
| 프로젝트 | 셀렉트 | 진행중(`ACTIVE`)·예정(`PLANNED`) 프로젝트만 노출 |
| 업무 영역 | 셀렉트 | 7개 고정값 |
| 담당자 | Slack 멤버 검색 | 활성 멤버 1명 |
| 마감일 | 날짜 | 과거일 선택 시 경고(차단은 하지 않음) |

**추가 정보 (선택)**

| 항목 | 컨트롤 | 비고 |
|---|---|---|
| 협업자 | Slack 멤버 검색 (다중) | 담당자와 중복 불가 |
| 시작일 | 날짜 | `시작일 ≤ 마감일` |
| 우선순위 | 셀렉트 | 기본 `보통` |
| 업무 설명 | 텍스트영역 | |

**외주 입력 항목** — 업무 영역 = `외주 작업` 선택 시 추가 표시

| 항목 | 컨트롤 | 필수 | 비고 |
|---|---|---|---|
| 외주 업체 | 텍스트(자동완성) | ✔ | 기존 업체명 재사용 |
| 외부 작업자 | 텍스트 | | 예: 홍길동 |
| 요청일 | 날짜 | | |
| 납품 예정일 | 날짜 | ✔ | 입력 시 마감일 기본값으로 채움 |
| 검수 상태 | 셀렉트 | | 기본 `미검수` |
| 작업 내용 | 텍스트영역 | | |

> 외주 작업에서 **내부 담당자는 별도 항목이 아니라 위의 `담당자`** 다.
> 화면 라벨만 "내부 담당자"로 바꿔 표기한다.

### 등록 시 동작

1. `status` 기본값 설정 — 일반 `대기`, 외주 `요청 예정`
2. `TASK_EVENT(CREATED)` 기록
3. 담당자에게 Slack DM 발송 (§09)
4. 협업자가 있으면 협업자에게도 DM 발송

### 등록 UX 원칙

- 필수 5개만 채우면 저장된다. 추가 정보는 접힌 상태로 시작한다.
- 등록 직후 목록 최상단에 하이라이트로 노출한다.
- **연속 등록** 지원: 저장 후 "계속 등록" 시 프로젝트·영역·담당자를 유지한 빈 폼을 연다.
  (주간 계획을 한 번에 입력하는 실제 사용 패턴)

## 4.2 업무 상태 전이

### 일반 업무

```
대기 ──→ 진행중 ──→ 검토 ──→ 완료
 ↑        ↑  ↓        ↓        │
 └────────┴──┴────────┴────────┘  (역방향 전이 허용)
```

- 모든 전이를 허용한다. 순서 강제는 하지 않는다. (기록 부담을 늘리지 않기 위함)
- 단, `완료 → 다른 상태`로 되돌릴 때는 확인 모달을 띄우고 `completed_at`을 비운다.

### 외주 작업

```
요청 예정 → 요청 완료 → 작업중 → 검수 → 수정 → 완료
                                  ↑______|
```

- `검수 ↔ 수정`은 반복될 수 있다.
- 검수 상태를 `반려`로 바꾸면 업무 상태를 `수정`으로 전환할지 제안한다.
- `완료` 처리 시 검수 상태가 `승인`이 아니면 경고한다. (차단하지 않음)

### 상태 변경 시 공통 동작

| 조건 | 동작 |
|---|---|
| 항상 | `TASK_EVENT(STATUS_CHANGED)` 기록 |
| → `검토` / `검수` | 프로젝트 리드에게 검토 요청 알림 |
| → `완료` | `completed_at` 기록, 담당자에게 확인 알림 없음(본인 조작) |
| 외주 → `완료` | `delivered_at`이 비어 있으면 오늘 날짜로 채울지 제안 |

```
┌──────────────────────────────────────────────┐
│ 관찰·평가 UX 개선                      [수정] │
│ Kinderverse · 기획              [진행중 ▾]   │
├──────────────────────────────────────────────┤
│ 담당자    (img) 김OO                          │
│ 협업자    (img) 박OO                          │
│ 일정      9/1 → 9/8   (D-2)                   │
│ 우선순위   보통                                │
├──────────────────────────────────────────────┤
│ 업무 설명                                     │
│ ...                                           │
├──────────────────────────────────────────────┤
│ 🔥 연결된 이슈 1건            [+ 이슈 등록]   │
│  · 디자인 시안 확정 지연   확인중   높음      │
├──────────────────────────────────────────────┤
│ 변경 이력                                     │
│  9/3 14:20  김OO  대기 → 진행중               │
│  9/1 09:10  김OO  업무 등록                   │
└──────────────────────────────────────────────┘
```

외주 작업일 때 추가 섹션:

```
├──────────────────────────────────────────────┤
│ 외주 정보                                     │
│ 외주 업체    OO 디자인                        │
│ 외부 작업자   홍길동                           │
│ 요청일       9/1                              │
│ 납품 예정    9/15   (D-3)                     │
│ 검수 상태    미검수                            │
```

## 4.4 Tasks 목록

| 컬럼 | 내용 |
|---|---|
| 업무 | 업무명 + ⚠/🔥 플래그 |
| 프로젝트 | 프로젝트명 |
| 영역 | 업무 영역 배지 |
| 담당 | 프로필 이미지 + 이름 |
| 마감 | `9/5` 형식. 지연 시 빨간색 + `(-3)` |
| 상태 | 상태 배지 (인라인 변경 가능) |
| 이슈 | 🔥 / `-` |

### 빠른 필터

`[전체] [내 담당 업무] [진행중] [검토] [지연] [이슈 있음] [외주 작업]`

- 기본 진입 시 **`[내 담당 업무]`** 를 선택 상태로 연다. (개인의 첫 화면은 본인 업무)
- 정렬 기본값: 마감일 오름차순 → 우선순위 → 등록일.
- 완료 업무는 기본으로 숨기고 `완료 포함` 토글로 노출한다.

### 목록 상태

| 상태 | 표시 |
|---|---|
| 최초 진입, 업무 0건 | "첫 업무를 등록해 보세요" + `+ 업무 등록` |
| 필터 결과 0건 | "조건에 맞는 업무가 없습니다" + `필터 초기화` |
| 로딩 | 스켈레톤 행 5개 |
| 오류 | "목록을 불러오지 못했습니다" + `다시 시도` |

## 4.5 외주 작업

외주는 **별도 메뉴가 아니라 업무 영역 값**이다. 동일한 Task 구조를 쓰고
외주 상세만 1:1로 확장한다. 전체 프로젝트 진행 현황에서는 내부 업무와 **함께 집계**한다.

| 구분 | 내부 업무 | 외주 작업 |
|---|---|---|
| 관리 단위 | Task | Task (동일) |
| 담당자 | Slack 멤버 | Slack 멤버 (내부 담당자) |
| 수행 주체 | 담당자 본인 | 외부 업체·작업자 (직접 입력) |
| 상태 체계 | 4단계 | 6단계 |
| 추가 관리 | - | 요청일, 납품 예정일, 검수 상태 |
| 집계 | 함께 | 함께 (필터로 분리 조회 가능) |

### 외주 전용 알림

- 납품 예정 D-2 / 당일 → 내부 담당자
- 납품 예정일 초과 → 내부 담당자 + 프로젝트 채널
- 검수 상태 `반려` → 내부 담당자
