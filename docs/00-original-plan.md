# KinderFlow MVP 기획서 (원본)

> 이 문서는 최초 작성된 기획서 원문이다. **기준 문서로 수정하지 않는다.**
> 이후 변경 사항은 각 스펙 문서(01~11)에 반영한다.

«업무의 담당을 명확히, 전체 흐름은 한눈에.»

## 1. 서비스 개요

- **서비스명**: KinderFlow
- **목적**: KinderFlow는 프로젝트와 구성원의 업무를 한곳에서 관리하고, 각 업무의 담당을 명확하게 정의하여 전체 진행 상황과 이슈를 한눈에 확인하기 위한 프로젝트·업무 관리 도구이다.

복잡한 프로젝트 관리 기능보다 실제 업무 진행에 필요한 다음 기능에 집중한다.

1. 업무 입력
2. 업무 담당 정의
3. 진행 확인
4. 이슈 관리
5. 주간 리포트

각 구성원이 수행하는 업무를 프로젝트와 연결하고, 업무별 담당과 진행 상태를 기록하면 프로젝트·업무 영역·담당자별 현황이 자동으로 집계되는 구조로 설계한다.

## 2. 핵심 관리 구조

```
프로젝트
   ↓
업무
   ↓
담당 정의
   ↓
진행 상태
   ↓
이슈
   ↓
주간 리포트
```

기본 관리 단위는 업무(Task)이다.

```
프로젝트
 └─ 업무
     ├─ 업무 영역
     ├─ 담당자
     ├─ 일정
     ├─ 진행 상태
     └─ 이슈
```

## 3. 업무 영역

| 업무 영역 | 주요 업무 |
|---|---|
| 프로젝트·사업관리 | 사업계획, 프로젝트 일정, 협업관리, 예산·계약, 의사결정, 보고 |
| 기획 | 서비스 기획, 정책, 요구사항, UX/UI 기획, 콘텐츠 기획, 기능 개선 |
| 개발 | 프론트엔드, 백엔드, AI, 인프라, 데이터, 개발 QA, 배포 |
| 마케팅 | 마케팅 기획, 콘텐츠, 홍보, 캠페인, 제안자료, SNS |
| 운영 | 서비스 운영, 콘텐츠 운영, 고객 대응, 운영 정책, 모니터링 |
| 외주 작업 | 외주 기획, 디자인, 개발, 콘텐츠 제작, 납품, 검수 및 수정 관리 |
| 기타 | 위 영역에 포함되지 않는 업무 |

## 4. 외주 작업 관리

외주 작업은 일반 내부 업무와 동일한 Task 구조를 사용하되, 외주 관리에 필요한 정보를 추가할 수 있다.

**외주 작업 항목**: 업무명 / 프로젝트 / 외주 업체·작업자 / 내부 담당자 / 작업 내용 / 요청일 / 납품 예정일 / 상태 / 검수 상태 / 이슈

**외주 작업 상태**

```
요청 예정 → 요청 완료 → 작업중 → 검수 → 수정 → 완료
```

내부 업무와 외주 작업은 전체 프로젝트 진행 현황에서는 함께 집계한다.

## 5. 업무 담당 정의

KinderFlow에서는 업무를 누군가에게 배정한다는 개념보다,

«"이 업무를 누가 담당하고 있는가?"»

를 명확하게 정의하는 것을 기본으로 한다. 업무 생성 또는 수정 시 담당자를 지정한다.

```
업무      관찰·평가 UX 개선
프로젝트   Kinderverse
업무 영역  기획
담당자     @김OO
협업자     @박OO
마감       9/8
```

## 6. 담당자 입력 — Slack

내부 구성원은 별도의 구성원 DB를 만들지 않고 Slack Workspace의 멤버 정보를 기준으로 한다.

```
담당자
🔍 Slack 멤버 검색
○ 김OO  @kim
○ 박OO  @park
○ 이OO  @lee
```

KinderFlow에는 다음 정보를 연결한다: Slack User ID / 이름 / 프로필 이미지

**담당 구분** — 필요한 경우 하나의 업무에 다음 두 역할을 정의한다.

- **담당자**: 업무 진행의 주 담당
- **협업자**: 함께 참여하거나 확인이 필요한 구성원

단, 담당자는 기본적으로 1명을 원칙으로 하여 책임 주체가 모호해지는 것을 방지한다.

## 7. 외주 작업의 담당 정의

외주 작업은 내부 담당자와 외부 작업자를 구분한다.

```
업무        활동지 디자인 제작
외주 업체    OO 디자인
외부 작업자  홍길동
내부 담당자  @김OO
납품 예정    9/15
현재 상태    작업중
```

외주 작업의 내부 담당자는 Slack 멤버를 기준으로 한다. 외부 업체와 작업자는 직접 입력한다.

## 8. 전체 메뉴

```
KinderFlow
├─ Overview
├─ Tasks
├─ Issues
└─ Weekly
```

외주 작업을 별도 메뉴로 분리하지 않고 Tasks의 업무 영역 중 하나로 관리한다. 필요할 경우 필터를 통해 외주 작업만 확인한다.

`[전체] [사업관리] [기획] [개발] [마케팅] [운영] [외주]`

## 9. 업무 입력

**기본 정보**: 업무명* / 프로젝트* / 업무 영역* / 담당자* / 마감일*

**추가 정보**: 협업자 / 시작일 / 우선순위 / 업무 설명

"업무 영역 = 외주 작업"을 선택하면 외주 입력 항목을 추가 표시한다.

외주 업체 / 외부 작업자 / 요청일 / 납품 예정일 / 검수 상태

## 10. 업무 상태

일반 업무는 네 단계로 관리한다.

```
대기 → 진행중 → 검토 → 완료
```

문제가 있는 경우 별도 상태로 표시한다.

- ⚠ 지연
- 🔥 이슈 있음

## 12. 담당자별 현황

Slack 구성원을 기준으로 업무 현황을 집계한다.

```
김OO
담당 업무 8 / 진행중 4 / 검토 1 / 완료 3 / 지연 0
████████░░ 72%
```

담당자를 선택하면 해당 담당자의 업무를 확인한다.

## 13. Tasks

| 업무 | 프로젝트 | 영역 | 담당 | 마감 | 상태 | 이슈 |
|---|---|---|---|---|---|---|
| 관찰 UX 설계 | Kinderverse | 기획 | @김OO | 9/5 | 진행중 | - |
| API 개발 | Kinderverse | 개발 | @박OO | 9/7 | 진행중 | 🔥 |
| 제안자료 | 사업 | 마케팅 | @이OO | 9/8 | 검토 | - |
| 운영 정책 | Kinderverse | 운영 | @최OO | 9/9 | 진행중 | - |
| 활동지 디자인 | 콘텐츠 | 외주 | @김OO | 9/15 | 작업중 | - |

**빠른 필터**: `[전체] [내 담당 업무] [진행중] [검토] [지연] [이슈 있음] [외주 작업]`

## 14. Issues

업무 진행 과정에서 발생하는 문제와 블로커를 관리한다.

이슈명* / 관련 프로젝트* / 관련 업무 / 내용* / 담당자* / 중요도 / 해결 목표일 / 상태

**상태**: `Open → 확인중 → 해결`

외주 관련 이슈도 동일한 Issues에서 관리한다. 예:

```
외주 디자인 납품 지연
관련 업무   활동지 디자인 제작
외주 업체   OO 디자인
내부 담당   @김OO
중요도      높음
영향        콘텐츠 등록 일정 3일 지연 예상
```

## 15. Weekly Report

업무 및 이슈 데이터를 기준으로 주간 리포트를 자동 생성한다.

1. 전체 업무 현황 — 완료 / 진행 / 검토 / 지연 업무 집계
2. 프로젝트별 진행 — 프로젝트별 진행률 및 주요 변화
3. 업무 영역별 진행 — 사업관리 / 기획 / 개발 / 마케팅 / 운영 / 외주 작업
4. 주요 완료 업무 — 이번 주 완료된 핵심 업무
5. 진행 및 지연 업무 — 진행 중 업무와 일정 지연 업무
6. 외주 진행 현황 — 진행 외주 6건 / 검수 2건 / 수정 1건 / 납품 지연 1건
7. 주요 이슈 — Open / 확인중 상태 이슈
8. 담당자별 현황 — 담당 업무 / 진행 / 완료 / 지연
9. 다음 주 주요 업무 — 다음 주 마감 예정 및 예정 업무

## 16. Slack 연동

Slack의 역할은 **구성원 정보 + 알림**이다.

- **구성원 연동**: Slack 멤버를 KinderFlow 담당자로 사용한다.
- **담당 업무 알림**: 새로운 업무의 담당자로 등록되면 알림을 제공한다.

```
KinderFlow
담당 업무가 등록되었습니다.
프로젝트  Kinderverse
업무      관찰·평가 UX 개선
마감      9월 8일
[업무 확인]
```

**주요 알림**: 담당 업무 등록 / 마감 D-1 / 오늘 마감 / 일정 지연 / 주요 이슈 발생 / 검토 요청 / 외주 납품 예정 / Weekly Report 공유

## 17. 서비스별 역할

```
                    KinderFlow
             프로젝트·업무 기준 데이터
                       │
        ┌──────────────┼──────────────┐
        ▼              ▼              ▼
      Slack      Google Calendar   Google Tasks
 구성원·알림       일정·마감        개인 할 일
```

KinderFlow가 Slack이나 Google의 기능을 대체하지 않는다.

## 18. MVP 핵심 범위

**Phase 1. 업무** — 프로젝트 생성 / 업무 입력 / 업무 영역 분류 / 외주 작업 등록 / Slack 구성원 연동 / 업무 담당 정의 / 협업자 정의 / 업무 상태 관리 / 담당자별 업무 조회 / 프로젝트별 업무 조회 / 지연 자동 표시

**Phase 2. 현황 및 이슈** — Overview / 프로젝트별 진행 현황 / 업무 영역별 진행 현황 / 담당자별 현황 / 외주 진행 현황 / Issues 등록 / Issues 해결 관리

**Phase 3. 리포트 및 Slack** — Weekly Report / 담당 업무 알림 / 마감 알림 / 검토 요청 / 이슈 알림 / 외주 납품 알림 / Weekly Report Slack 공유

**Phase 4. Google** — Google Calendar / Google Tasks / 마일스톤 연동

## 19. 핵심 원칙

1. 업무를 배정하는 시스템이 아니라 업무의 담당을 명확히 정의한다.
2. 프로젝트와 개인 업무가 연결되어야 한다.
3. 사업관리·기획·개발·마케팅·운영·외주 작업을 구분한다.
4. 내부 담당자는 Slack을 기준으로 한다.
5. 외주 작업은 외부 작업자와 내부 담당자를 함께 관리한다.
6. 업무 상태와 이슈 상태를 분리한다.
7. 개별 업무를 관리하면 전체 현황이 자동으로 집계된다.
8. 별도 보고 작업 없이 Weekly Report가 생성되어야 한다.

## 20. KinderFlow 한 줄 정의

«프로젝트의 업무와 담당을 명확히 정의하고, 내부 업무와 외주 작업의 진행·이슈를 추적하여 전체 업무 흐름을 한눈에 보여주는 프로젝트·업무 관리 도구.»
