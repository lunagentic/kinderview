# 10. 로드맵 및 백로그

## 10.1 Phase 구성

| Phase | 목표 | 완료 판단 |
|---|---|---|
| **1. 업무** | 업무와 담당을 기록할 수 있다 | 팀이 실제 주간 업무를 KinderFlow에 등록하기 시작한다 |
| **2. 현황 및 이슈** | 기록된 업무가 현황으로 보인다 | 회의에서 Overview 화면을 띄워놓고 진행을 확인한다 |
| **3. 리포트 및 Slack** | 보고와 알림이 자동으로 돈다 | 주간 보고를 위한 별도 취합 작업이 사라진다 |
| **4. Google** | 일정이 개인 도구와 연결된다 | 마감일이 개인 캘린더에 보인다 |

Phase 1~3이 MVP다. Phase 4는 MVP 이후.

## 10.2 Phase 1 — 업무

| # | 항목 | 유저스토리 | 수용 기준 |
|---|---|---|---|
| 1-1 | Slack 로그인 | 팀원으로서 Slack 계정으로 로그인하고 싶다 | Slack OAuth로 로그인되며, 워크스페이스 멤버만 접근 가능 |
| 1-2 | Slack 구성원 연동 | 별도 가입 없이 팀원이 담당자로 나오길 원한다 | `users.list` 동기화, 봇·삭제 사용자 제외, 일 1회 자동 + 수동 실행 |
| 1-3 | 프로젝트 생성 | 업무를 묶을 프로젝트를 만들고 싶다 | 이름·상태·기간·리드 입력, 목록/수정/아카이브 |
| 1-4 | 업무 입력 | 업무를 프로젝트에 연결해 기록하고 싶다 | 필수 5개(업무명·프로젝트·영역·담당자·마감일)로 저장 가능 |
| 1-5 | 업무 영역 분류 | 영역별로 업무를 구분하고 싶다 | 7개 고정 영역 단일 선택, 목록 필터 동작 |
| 1-6 | 업무 담당 정의 | 이 업무를 누가 담당하는지 명확히 하고 싶다 | 담당자 필수·단일. 미지정 저장 불가 |
| 1-7 | 협업자 정의 | 함께 보는 사람을 표시하고 싶다 | 0~N명 지정, 담당자 중복 불가 |
| 1-8 | 외주 작업 등록 | 외주도 같은 방식으로 관리하고 싶다 | 영역=외주 선택 시 외주 항목 표시, 업체·납품 예정일 필수 |
| 1-9 | 업무 상태 관리 | 진행 상태를 갱신하고 싶다 | 일반 4단계 / 외주 6단계, 목록에서 인라인 변경, 이력 기록 |
| 1-10 | 지연 자동 표시 | 밀린 업무가 저절로 드러나길 원한다 | 마감일 초과 미완료 업무에 ⚠ 자동 표시 (수동 입력 없음) |
| 1-11 | 담당자별 업무 조회 | 내 담당 업무만 보고 싶다 | `내 담당 업무` 필터, 담당자별 필터 |
| 1-12 | 프로젝트별 업무 조회 | 프로젝트 단위로 보고 싶다 | 프로젝트 필터, URL에 필터 유지 |

**Phase 1 종료 조건**
- 담당자 미지정 업무를 만들 수 없다.
- 내부 업무와 외주 작업이 하나의 목록에서 함께 조회된다.
- 마감일이 지난 업무가 자동으로 지연 표시된다.

## 10.3 Phase 2 — 현황 및 이슈

| # | 항목 | 유저스토리 | 수용 기준 |
|---|---|---|---|
| 2-1 | Overview 요약 | 전체 현황을 한 화면에서 보고 싶다 | 6개 요약 카드, 클릭 시 해당 조건 Tasks로 이동 |
| 2-2 | 프로젝트별 진행 현황 | 프로젝트가 얼마나 진행됐는지 알고 싶다 | 가중 진행률(%) 표시, 업무 0건은 `-` |
| 2-3 | 업무 영역별 진행 현황 | 영역별 부하를 보고 싶다 | 7개 영역 진행률, 외주 포함 |
| 2-4 | 담당자별 현황 | 누가 얼마나 맡고 있는지 보고 싶다 | 담당/진행/검토/완료/지연 + 진행률, 클릭 시 필터 이동 |
| 2-5 | 외주 진행 현황 | 외주 상태를 한눈에 보고 싶다 | 진행·검수·수정·납품 지연 건수 |
| 2-6 | Issues 등록 | 블로커를 기록하고 싶다 | 이슈명·프로젝트·내용·담당자 필수, 업무 연결 선택 |
| 2-7 | Issues 해결 관리 | 이슈 해결 과정을 추적하고 싶다 | Open→확인중→해결, 미해결 이슈가 업무에 🔥 표시 |
| 2-8 | 업무-이슈 연결 | 어떤 업무가 막혀 있는지 알고 싶다 | 업무 상세에 연결 이슈 목록, 업무 상세에서 이슈 등록 |

**Phase 2 종료 조건**
- Overview의 모든 숫자에서 원본 업무 목록으로 내려갈 수 있다.
- 업무 상태와 이슈 상태가 서로를 자동 전이시키지 않는다.

## 10.4 Phase 3 — 리포트 및 Slack

| # | 항목 | 유저스토리 | 수용 기준 |
|---|---|---|---|
| 3-1 | Weekly Report 생성 | 별도 취합 없이 주간 리포트를 얻고 싶다 | 9개 섹션 자동 생성, 사람 입력 필드 0개 |
| 3-2 | 리포트 스냅샷 | 지난 리포트가 바뀌지 않길 원한다 | 생성 시점 스냅샷 저장, 이전/다음 주 조회 |
| 3-3 | 담당 업무 알림 | 내가 담당이 되면 알고 싶다 | 담당자 지정 시 Slack DM, 본인 액션은 제외 |
| 3-4 | 마감 알림 | 마감을 놓치지 않고 싶다 | D-1 18:00 / 당일 09:00, 담당자별 묶음 발송 |
| 3-5 | 지연 알림 | 밀린 업무를 다시 인지하고 싶다 | 매일 09:30, 담당자 DM + 프로젝트 채널, 동일 건 1일 1회 |
| 3-6 | 검토 요청 알림 | 검토가 필요할 때 알고 싶다 | 상태 → 검토/검수 시 프로젝트 리드에게 발송 |
| 3-7 | 이슈 알림 | 중요 이슈를 즉시 알고 싶다 | 중요도 높음 이슈 등록 시 담당자 DM + 채널 |
| 3-8 | 외주 납품 알림 | 납품일을 챙기고 싶다 | D-2 / 당일 / 지연 알림, 내부 담당자 대상 |
| 3-9 | Weekly Report Slack 공유 | 리포트를 팀에 자동 공유하고 싶다 | 금 17:05 지정 채널 게시, 요약 + 링크 |
| 3-10 | 알림 설정 | 필요한 알림만 받고 싶다 | 종류별 on/off (마감·지연 제외) |

**Phase 3 종료 조건**
- 주간 보고를 위한 수동 취합 작업이 사라진다.
- 담당자가 자기 마감을 Slack에서 인지한다.

## 10.5 Phase 4 — Google (MVP 이후)

| # | 항목 | 내용 |
|---|---|---|
| 4-1 | Google Calendar | 담당 업무 마감일을 개인 캘린더에 반영 |
| 4-2 | Google Tasks | 담당 업무를 개인 할 일로 내보내기 |
| 4-3 | 마일스톤 연동 | 프로젝트 주요 일정을 캘린더 이벤트로 관리 |

KinderFlow가 Google의 기능을 대체하지 않는다. **단방향 반영**을 기본으로 하고,
역방향 동기화는 하지 않는다. (일정의 원천은 KinderFlow)

## 10.6 결정 필요 사항

| # | 항목 | 현재 가정 | 결정 필요 시점 |
|---|---|---|---|
| D-1 | 업무 규모 가중치 반영 여부 | 모든 업무 동일 비중 | Phase 2 착수 전 |
| D-2 | 타인 업무 상태 변경 허용 여부 | 허용 + 변경자 이력 | Phase 1 착수 전 |
| D-3 | Weekly Report 자동 게시 vs 확인 후 게시 | 자동 게시 (5분 수정 여유) | Phase 3 착수 전 |
| D-4 | 프로젝트 채널 알림의 기본 채널 | 단일 기본 채널 | Phase 3 착수 전 |
| D-5 | 진행률 산식 (가중 평균 vs 완료율) | 가중 평균 | Phase 2 착수 전 |
| D-6 | 모바일 업무 등록 지원 범위 | 조회·상태 변경까지만 | Phase 2 착수 전 |

## 10.7 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| 업무 기록이 습관화되지 않음 | 모든 집계가 무의미해진다 | 필수 입력 5개로 최소화, 연속 등록 지원, 마감 알림으로 재진입 유도 |
| 담당자 1명 원칙에 대한 현장 저항 | 담당 필드가 형식적으로 채워진다 | 협업자로 흡수, "나누라"는 안내를 UI에서 제공 |
| 외주 정보를 내부 담당자가 대신 기록하는 부담 | 외주 현황이 최신이 아님 | 납품 D-2 알림으로 갱신 시점을 만든다 |
| Slack 알림 과다로 인한 무시(알림 피로) | 알림 효용 상실 | 묶음 발송, 1일 1회 제한, 자기 액션 억제, 종류별 on/off |
| 지연 업무가 계속 쌓여 지표가 무뎌짐 | 지연 표시를 무시하게 된다 | Weekly에 지연 일수 내림차순 노출, 마감일 재설정 유도 |
