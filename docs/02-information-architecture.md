# 02. 정보 구조 (IA)

## 2.1 핵심 관리 구조

```
프로젝트 → 업무 → 담당 정의 → 진행 상태 → 이슈 → 주간 리포트
```

기본 관리 단위는 **업무(Task)** 이다.

```
프로젝트
 └─ 업무
     ├─ 업무 영역
     ├─ 담당자 (1명 원칙)
     ├─ 협업자 (0~N명)
     ├─ 일정 (시작일 / 마감일)
     ├─ 진행 상태
     ├─ 외주 정보 (업무 영역 = 외주 작업일 때)
     └─ 이슈 (0~N건)
```

## 2.2 메뉴 구조

```
KinderFlow
├─ Overview        전체 현황 대시보드
├─ Tasks           업무 목록 · 등록 · 상세
├─ Issues          이슈 목록 · 등록 · 상세
└─ Weekly          주간 리포트
```

외주 작업은 **별도 메뉴로 분리하지 않는다.** Tasks의 업무 영역 값 중 하나로 관리하고,
필요할 때 필터로 외주만 조회한다.

### 화면 계층

| 뎁스 | 화면 | 진입 경로 |
|---|---|---|
| 1 | Overview | GNB |
| 1 | Tasks 목록 | GNB |
| 2 | 업무 등록/수정 | Tasks 목록의 `+ 업무 등록`, 상세의 `수정` |
| 2 | 업무 상세 | Tasks 목록 행 클릭 |
| 1 | Issues 목록 | GNB |
| 2 | 이슈 등록/수정 | Issues 목록의 `+ 이슈 등록`, 업무 상세의 `이슈 등록` |
| 2 | 이슈 상세 | Issues 목록 행 클릭 |
| 1 | Weekly | GNB |
| 2 | 담당자별 업무 목록 | Overview 담당자 카드 클릭 → Tasks(담당자 필터) |
| 2 | 프로젝트별 업무 목록 | Overview 프로젝트 바 클릭 → Tasks(프로젝트 필터) |

> Overview의 모든 집계 항목은 **클릭 시 해당 조건이 적용된 Tasks 목록으로 이동**한다.
> (숫자에서 원본 업무로 바로 내려갈 수 있어야 한다)

## 2.3 업무 영역

| 코드 | 업무 영역 | 주요 업무 |
|---|---|---|
| `PLAN` | 서비스기획 | 서비스 기획, 정책, 요구사항, UX/UI 기획, 기능 개선 |
| `DEV` | 개발 | 프론트엔드, 백엔드, AI, 인프라, 데이터, 개발 QA, 배포 |
| `CONTENT` | 콘텐츠 | 콘텐츠 기획·제작, 활동지·교안, 영상, 리소스 검수, 콘텐츠 성과 분석 |
| `BIZ` | 사업전략 | 사업계획, 제안·투자 자료, 예산·계약, 파트너십, 의사결정, 보고 |
| `OPS` | 운영 | 서비스 운영, 콘텐츠 운영, 고객 대응, 운영 정책, 모니터링 |
| `OUT` | 외주 작업 | 외주 기획, 디자인, 개발, 콘텐츠 제작, 납품, 검수 및 수정 관리 |
| `ETC` | 기타 | 위 영역에 포함되지 않는 업무 |

- 업무 영역은 **단일 선택**이다. (복수 영역에 걸치는 업무는 업무를 나눈다)
- `OUT`을 선택하면 외주 입력 항목이 추가로 표시된다.
- 영역 목록은 MVP에서 **고정값**으로 관리한다. (사용자 추가/편집 불가)

### 영역 필터 (Tasks 상단)

`[전체] [서비스기획] [개발] [콘텐츠] [사업전략] [운영] [외주] [기타]`

## 2.4 공통 필터 규약

Tasks / Issues / Overview에서 공통으로 사용하는 필터 파라미터.

| 파라미터 | 값 | 비고 |
|---|---|---|
| `project` | 프로젝트 ID | 다중 선택 가능 |
| `area` | 업무 영역 코드 | 다중 선택 가능 |
| `owner` | Slack User ID | `me` = 로그인 사용자 |
| `status` | 업무 상태 코드 | 다중 선택 가능 |
| `flag` | `delayed` / `has_issue` | 상태와 별개인 플래그 |
| `due_from`, `due_to` | 날짜 | 마감일 범위 |
| `q` | 문자열 | 업무명·설명 검색 |

필터 상태는 **URL 쿼리에 유지**한다. 링크를 그대로 공유하면 동일 화면이 열려야 한다.
(Slack 알림에서 필터가 적용된 목록으로 바로 연결하기 위함)


## 2.5 변경 이력

| 날짜 | 변경 | 사유 |
|---|---|---|
| 2026-09-03 | 업무 영역 개편 — `마케팅` 제거, `콘텐츠` 신설. `기획`→`서비스기획`, `프로젝트·사업관리`→`사업전략` | 팀의 실제 직능 구분(서비스기획·개발·콘텐츠·사업전략·운영)에 맞춤. 마케팅 업무는 성격에 따라 콘텐츠 또는 사업전략으로 나뉜다 |

기존 데이터의 `MKT` 는 앱 시작 시 자동으로 `BIZ`(사업전략)로 옮겨진다(`server/migrate.js`).
콘텐츠 성격이던 업무는 화면에서 다시 선택하면 된다.
