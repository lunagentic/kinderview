# 02. 정보 구조 (IA)

## 2.1 핵심 관리 구조

```
프로젝트 → 업무 → 담당 정의 → 진행 상태 → 이슈 → 주간 리포트
```

기본 관리 단위는 **업무(Task)** 이다.

```
프로젝트
 └─ 업무
     ├─ 업무 영역
     ├─ 담당자 (1명 원칙)
     ├─ 협업자 (0~N명)
     ├─ 일정 (시작일 / 마감일)
     ├─ 진행 상태
     ├─ 외주 정보 (업무 영역 = 외주 작업일 때)
     └─ 이슈 (0~N건)
```

## 2.2 메뉴 구조

```
KinderFlow
├─ 프로젝트 매니징   현황 · 업무 · 이슈 · 주간 리포트  (2차 탭)
├─ 타임트래킹        내 타임시트 · 투입 집계
└─ 인보이싱          외주 지급
                    알림함은 상단 우측 보조 메뉴
```

상세는 [13-타임트래킹·인보이싱](13-time-invoice-spec.md) 참조.

외주 작업은 **별도 메뉴로 분리하지 않는다.** Tasks의 업무 영역 값 중 하나로 관리하고,
필요할 때 필터로 외주만 조회한다.

### 화면 계층

| 뎁스 | 화면 | 진입 경로 |
|---|---|---|
| 1 | Overview | GNB |
| 1 | Tasks 목록 | GNB |
| 2 | 업무 등록/수정 | Tasks 목록의 `+ 업무 등록`, 상세의 `수정` |
| 2 | 업무 상세 | Tasks 목록 행 클릭 |
| 1 | Issues 목록 | GNB |
| 2 | 이슈 등록/수정 | Issues 목록의 `+ 이슈 등록`, 업무 상세의 `이슈 등록` |
| 2 | 이슈 상세 | Issues 목록 행 클릭 |
| 1 | Weekly | GNB |
| 2 | 담당자별 업무 목록 | Overview 담당자 카드 클릭 → Tasks(담당자 필터) |
| 2 | 프로젝트별 업무 목록 | Overview 프로젝트 바 클릭 → Tasks(프로젝트 필터) |

> Overview의 모든 집계 항목은 **클릭 시 해당 조건이 적용된 Tasks 목록으로 이동**한다.
> (숫자에서 원본 업무로 바로 내려갈 수 있어야 한다)

## 2.3 업무 영역

| 코드 | 업무 영역 | 주요 업무 |
|---|---|---|
| `PLAN` | 서비스기획 | 서비스 기획, 정책, 요구사항, 기능 개선, 화면 흐름 |
| `DESIGN` | 디자인 | UI/UX 디자인, 시안, 그래픽·일러스트, 아이콘, 레이아웃 |
| `DEV` | 개발 | 프론트엔드, 백엔드, AI, 인프라, 데이터, 개발 QA, 배포 |
| `CONTENT` | 콘텐츠 | 콘텐츠 기획·제작, 활동지·교안, 영상, 리소스 검수 |
| `MKT` | 마케팅 | 마케팅 기획, 홍보, 캠페인, SNS, 제안자료 |
| `BIZ` | 사업전략 | 사업계획, 투자·파트너십, 예산·계약, 의사결정, 보고 |
| `OPS` | 운영 | 서비스 운영, 콘텐츠 운영, 고객 대응, 운영 정책, 모니터링 |
| `OUT` | 외주 작업 | 외주 기획, 디자인, 개발, 콘텐츠 제작, 납품, 검수 및 수정 관리 |
| `ETC` | 기타 | 위 영역에 포함되지 않는 업무 |

- 업무 영역은 **단일 선택**이며, **업무의 담당자를 결정한다** — 선택한 영역의 리드가 담당이 된다.
  (복수 영역에 걸치는 업무는 업무를 나눈다)
- `OUT`을 선택하면 외주 입력 항목이 추가로 표시된다.
- 영역 목록은 MVP에서 **고정값**으로 관리한다. (사용자 추가/편집 불가)

### 영역 필터 (Tasks 상단)

`[전체] [서비스기획] [디자인] [개발] [콘텐츠] [마케팅] [사업전략] [운영] [외주] [기타]`

## 2.4 공통 필터 규약

Tasks / Issues / Overview에서 공통으로 사용하는 필터 파라미터.

| 파라미터 | 값 | 비고 |
|---|---|---|
| `project` | 프로젝트 ID | 다중 선택 가능 |
| `area` | 업무 영역 코드 | 다중 선택 가능 |
| `owner` | Slack User ID | `me` = 로그인 사용자 |
| `status` | 업무 상태 코드 | 다중 선택 가능 |
| `flag` | `delayed` / `has_issue` | 상태와 별개인 플래그 |
| `due_from`, `due_to` | 날짜 | 마감일 범위 |
| `q` | 문자열 | 업무명·설명 검색 |

필터 상태는 **URL 쿼리에 유지**한다. 링크를 그대로 공유하면 동일 화면이 열려야 한다.
(Slack 알림에서 필터가 적용된 목록으로 바로 연결하기 위함)


## 2.5 변경 이력

| 날짜 | 변경 | 사유 |
|---|---|---|
| 2026-09-03 | 업무 영역 개편 — `콘텐츠` 신설, `기획`→`서비스기획`, `프로젝트·사업관리`→`사업전략` | 팀의 실제 직능 구분에 맞춤 |
| 2026-09-04 | `디자인` 신설, `마케팅` 유지 확정 | 디자인과 마케팅을 별도 직능으로 관리 |
| 2026-09-04 | **담당 구조 변경** — 업무마다 담당자를 고르지 않고 **영역 리드가 담당**이 된다 | 소규모 팀에서 업무별 인원 배정은 관리 비용만 늘린다. 책임은 영역 단위로 정의한다 |
| 2026-09-05 | **메뉴 3개로 재편** — 프로젝트 매니징 / 타임트래킹 / 인보이싱 | 레퍼런스 제품의 기능 구성을 따름. 기존 화면은 프로젝트 매니징의 2차 탭으로 이동 |

기존 데이터의 영역 값은 그대로 유지된다. 앱 시작 시 제약만 넓히는 마이그레이션이 돈다(`server/migrate.js`).
