# 05. 담당 정의 스펙

## 5.1 기본 개념

KinderFlow는 업무를 **배정(assign)** 하지 않는다.
"이 업무를 **누가 담당하고 있는가**"를 명확히 **정의(define)** 한다.

| 배정 시스템 | KinderFlow |
|---|---|
| 관리자가 구성원에게 일을 내린다 | 진행 중인 업무의 책임 주체를 기록한다 |
| 미배정 상태가 존재한다 | 담당자 없는 업무는 존재할 수 없다 |
| 수락/거절 개념 | 없음. 사실을 기록할 뿐 |
| 여러 명에게 배정 | 담당자는 1명. 나머지는 협업자 |

이 차이가 UI 문구에도 반영된다.

| 지양 | 사용 |
|---|---|
| 업무를 배정했습니다 | 담당 업무가 등록되었습니다 |
| 담당자 할당 | 담당자 |
| 미배정 | (존재하지 않음) |

## 5.2 담당 구분

| 역할 | 인원 | 정의 | 알림 |
|---|---|---|---|
| **담당자** | 1명 (필수) | 업무 진행의 주 담당. 상태를 갱신할 책임 주체 | 등록, 마감, 지연, 검수, 이슈 |
| **협업자** | 0~N명 | 함께 참여하거나 확인이 필요한 구성원 | 등록 시 1회 |

- 담당자는 **1명 원칙**이다. 책임 주체가 모호해지는 것을 방지한다.
- 담당자를 2명 이상 지정하고 싶은 상황은 대부분 **업무를 나눠야 하는 신호**다.
  UI에서 담당자 2명을 시도하면 "업무를 나누거나 협업자로 추가하세요" 안내를 노출한다.
- 담당자 변경 시 `TASK_EVENT(OWNER_CHANGED)`를 남기고 신규 담당자에게 알림을 보낸다.

## 5.3 Slack 멤버 연동

내부 구성원은 **별도의 구성원 DB를 만들지 않고** Slack Workspace 멤버를 기준으로 한다.

### 연결하는 정보

| KinderFlow | Slack API 필드 |
|---|---|
| Slack User ID | `user.id` |
| 이름 | `user.profile.display_name` (없으면 `real_name`) |
| 프로필 이미지 | `user.profile.image_72` |
| 이메일 | `user.profile.email` (권한 있을 때) |

### 동기화

| 항목 | 정책 |
|---|---|
| 방식 | `users.list` 전체 조회 후 upsert |
| 주기 | 1일 1회 (매일 08:00) + 관리 화면의 `지금 동기화` 수동 실행 |
| 제외 대상 | `is_bot = true`, `deleted = true`, `Slackbot` |
| 퇴사/삭제 | 레코드 삭제하지 않고 `is_active = false` |
| 신규 멤버 | 자동 추가. 별도 초대 절차 없음 |

### 담당자 선택 UI

```
담당자 *
┌────────────────────────────┐
│ 🔍 Slack 멤버 검색          │
├────────────────────────────┤
│ (img) 김OO      @kim        │
│ (img) 박OO      @park       │
│ (img) 이OO      @lee        │
└────────────────────────────┘
```

- 이름·Slack 핸들·이메일로 검색한다.
- 최근 지정한 담당자 3명을 상단에 노출한다.
- 비활성 멤버는 검색 결과에 노출하지 않는다. 단, 기존 업무의 담당자로는 계속 표시하고
  `(비활성)` 배지를 붙인다.

### 비활성 멤버 처리

퇴사·삭제된 멤버가 담당인 업무가 남을 수 있다. 이때:

- Overview 담당자별 현황에 **`인수인계 필요 N건`** 섹션으로 별도 노출한다.
- 해당 업무는 프로젝트/영역 집계에서는 정상 포함한다.

## 5.4 외주 작업의 담당 정의

외주는 **내부 담당자**와 **외부 작업자**를 구분한다.

| 구분 | 값의 출처 | 필수 |
|---|---|---|
| 내부 담당자 | Slack 멤버 (`task.owner_slack_user_id`) | ✔ |
| 외주 업체 | 직접 입력 (자동완성) | ✔ |
| 외부 작업자 | 직접 입력 | |

```
업무        활동지 디자인 제작
외주 업체    OO 디자인
외부 작업자  홍길동
내부 담당자  @김OO
납품 예정    9/15
현재 상태    작업중
```

- 외부 업체·작업자는 KinderFlow 계정이 아니다. 알림 대상도 아니다.
- 담당자별 현황·알림은 모두 **내부 담당자 기준**으로 동작한다.
  외주 업무의 진행 책임은 외부가 아니라 내부 담당자에게 있다. (원칙 5)

## 5.5 로그인과 사용자 식별

| 항목 | MVP 정책 |
|---|---|
| 로그인 | Slack OAuth (`Sign in with Slack`) |
| 사용자 식별 | Slack User ID |
| 권한 | 전원 동일. 모든 프로젝트·업무 조회·편집 가능 |
| 워크스페이스 | 단일 워크스페이스 전제 |
