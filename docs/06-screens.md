### 보드 지도 — 이 화면의 히어로

> 2026-09-05 변경. 숫자 카드 6칸을 그래프 하나로 바꿨다. 같은 숫자를 담으면서
> **구성**까지 보여주고, 타일 하나하나가 원본 업무로 가는 문이 된다.

**업무 하나가 타일 하나다.** 넓이가 아니라 개수로 센다.

| 채널 | 나타내는 것 |
|---|---|
| 가로 위치(열) | 진행 단계 — 대기 → 진행중 → 검토 → 완료 |
| 타일 색 | 프로젝트 (4칸 팔레트, [14 §14.3](14-timeline-spec.md)) |
| 빨간 테두리 | 지연. 상태색은 여기에만 쓴다 |
| 타일 개수 | 업무 수 |

한 채널이 한 가지만 나타낸다. 타일 크기는 어디서나 같다 — 크기가 뜻을 갖지 않도록.

**색만으로 구분하게 두지 않는다.** 열 머리에 개수가 적혀 있고, 같은 프로젝트끼리
붙여 두며, 아래 범례와 타일 툴팁이 이름을 말한다.

| 요소 | 산식 | 클릭 시 |
|---|---|---|
| 히어로 숫자 | 전체 진행률 ([03 §3.5](03-data-model.md) 상태 가중 평균) | — |
| 대기 | `TODO` + `REQUEST_PLANNED` + `REQUESTED` | Tasks(대기) |
| 진행중 | `IN_PROGRESS` + `OUT_IN_PROGRESS` + `OUT_REVISION` | Tasks(진행중) |
| 검토 | `REVIEW` + `OUT_REVIEW` | Tasks(검토) |
| 완료 | `DONE` | Tasks(완료) |
| 타일 | 업무 1건 | 그 업무 상세 |
| 지연 | `is_delayed = true` | Tasks(지연) |
| 이슈 | `status ∈ {OPEN, CHECKING}` 인 이슈 건수 | Issues(미해결) |

> 지연·이슈 칩은 값이 0보다 크면 강조 색으로 표시한다. 0이면 회색.
> 한 열의 타일이 72개를 넘으면 접고 `+N` 으로 남은 수만 알린다.

### 섹션별 규칙

| 섹션 | 정렬 | 표시 상한 | 클릭 시 |
|---|---|---|---|
| 프로젝트별 진행 | `sort_order` → 이름 | 전체 | Tasks(프로젝트 필터) |
| 업무 영역별 진행 | 고정 순서 (서비스기획→기타). 각 행에 리드 표시 | 전체 | Tasks(영역 필터) |
| 외주 진행 현황 | - | - | Tasks(외주 필터) |

- 진행률 산식은 [03-데이터 모델 §3.5](03-data-model.md#35-진행률-산식) 참조.
- 업무 0건 항목은 진행률을 `-`로 표기한다.

### 기간 기준

Overview는 **현재 시점 스냅샷**이다. 기간 필터를 두지 않는다.
기간별 변화는 Weekly에서 본다.

## 6.3 영역 리드

Overview 에 **담당자별 현황 섹션은 두지 않는다.** 담당은 사람이 아니라 영역 단위로 관리한다.

- 업무 영역별 진행의 각 행에 그 영역의 **리드**를 함께 보여준다
- `리드 관리` 버튼으로 영역별 리드를 지정한다
- 리드를 바꾸면 그 영역의 **미완료 업무** 담당이 함께 옮겨진다. 완료된 업무는 당시 담당자를 유지한다
- 리드가 비어 있거나 비활성인 영역은 **위험 신호**(`HANDOVER`)로 올라온다

```
영역 리드
──────────────────────────
서비스기획      김OO  ▾
디자인         정OO  ▾
개발           박OO  ▾
콘텐츠         정OO  ▾
마케팅         이OO  ▾
사업전략        이OO  ▾
운영           최OO  ▾
외주 작업       김OO  ▾
기타           김OO  ▾
```

한 사람이 여러 영역의 리드를 겸할 수 있다.

## 6.4 업무

[04-업무 스펙 §4.4](04-task-spec.md#44-tasks-목록) 참조. 2026-09-06 에 구조를 바꿨다.

**마감이 맨 앞이다.** 이 화면은 "언제까지 무엇을"을 보는 곳이라 가장 먼저 읽혀야 하는 값이 날짜다.
기본 정렬도 마감일 순.

**묶음은 프로젝트 › 영역 › 업무.** 영역이 곧 담당이라 이 층이 책임 단위가 된다.
영역 머리에는 그 영역의 리드가 함께 나온다.

**월 필터가 맨 위에 있다.** `전체 · 9월 · 10월 · 11월` — 업무가 걸린 달만 나오고
(`GET /api/task-months`), 달마다 건수와 지연 건수를 함께 보여 준다.
조건 없이 들어오면 **이번 달**부터 열린다. 달을 고른 상태에서 업무를 등록하면
마감일이 그 달 말일로 미리 채워진다.

> `month=all` 은 "달을 안 고름"이다. 파라미터를 아예 지우면 이번 달로 되돌아가므로
> 전체 보기는 값으로 남긴다.

### 링크·첨부
업무 상세 왼쪽 열, 업무 정보 아래 「링크·첨부」 패널. 링크는 주소를 붙여넣어 더하고(이름은 비면 도메인/경로), 이미지는 「이미지 올리기」·끌어다 놓기·클립보드 붙여넣기로 더한다. 주소 글자를 끌어다 놓으면 링크가 된다. 둘 다 새 창에서 열린다. 보기 전용에서는 보기만 된다. 하위 업무 창에는 첨부가 칩으로만 보이고(더하기는 상세에서), 제목에 주소가 든 하위 업무는 ↗ 로 바로 연다. 설명·하위 업무 제목·코멘트 속 주소는 자동으로 링크가 된다.

### 디렉터 코멘트가 열리는 곳
업무 상세 외에 **하위 업무 창**(타임라인 줄·업무 탭 줄 클릭)과 **타임라인 업무 줄의 종이비행기 뱃지**에서도 같은 코멘트를 읽고 남긴다. 뱃지는 디렉터 코멘트가 있으면 디렉터 표시와 수, 아니면 비행기(코멘트 수)로 선다. **페이즈 줄**에도 같은 뱃지가 있어 페이즈 전체에 대한 코멘트를 남긴다(업무 코멘트와 같은 부품, 자리만 페이즈).

디렉터 자리에서 남긴 말은 디렉터 코드로 들어온 사람이 고치고 지울 수 있다(사람이 아니라 자리의 말이므로). 관리자도 지울 수 있다.

**누가 어디에 쓰나.** 「디렉터 코멘트」 칸은 디렉터 코드로 들어온 사람만 쓴다. 편집 코드·관리자 코드로 들어온 사람은 그 아래 「댓글」 칸에 남긴다. 둘 다 서로의 글에 답글을 달 수 있고, 디렉터가 남의 댓글에 단 답글은 그 사람의 말로 남는다(디렉터 칸에서 쓴 글만 디렉터 자리의 말이다). 디렉터 코멘트가 없으면 「아직 디렉터 코멘트가 없습니다」가 서고 글쓰기 칸은 안 보인다.

**지우면 사라진다.** 「지운 코멘트입니다」 자리를 남기지 않고 행을 지운다. 답글이 딸려 있었으면 답글은 뿌리 글로 올라선다 — 남의 말까지 따라 지우지는 않는다.

### 디렉터 코멘트 모아보기
타임라인 범례 줄 오른쪽 끝의 「디렉터 코멘트 N」 단추. 누구나(보기 전용 포함) 누를 수 있고, 업무·페이즈에 달린 디렉터 코멘트가 최신순으로 선다. 줄을 누르면 그 글로 간다 — 업무면 상세의 코멘트 칸으로 내려가 잠깐 밝히고, 페이즈면 페이즈 코멘트 창이 그 글에서 열린다.

## 6.4.1 타임라인

[14-타임라인 스펙](14-timeline-spec.md) 참조.

간트는 프로젝트 매니징의 **첫 탭이자 진입 화면**이다(2026-09-05 변경).

**2차 탭은 끌어서 순서를 바꿀 수 있다**(2026-09-06). 마우스·터치 모두 되고,
키보드는 `Alt + ← →`. 순서는 그 브라우저에만 저장되고(`localStorage: kf.tabs`),
저장이 막힌 환경에서는 기본 순서로 동작한다.
**첫 칸이 곧 진입 화면**이라, 순서를 바꾸면 들어왔을 때 보이는 화면도 함께 바뀐다. 페이즈 막대와 마일스톤 마름모를 한 창에 그린다.
좁은 화면에서는 **차트 안에서만 가로로 스크롤**하고 페이지 본문은 흔들지 않는다.

## 6.6-2 간트 (먼데이식 표)

주간 리포트 자리의 탭. **마감 달 기준**으로 「이번 달」「지난 달」 두 묶음(‹ › 로 달을 옮기면 그 달과 그 전 달)에 **페이즈가 한 줄씩**(상위 항목) 선다 — 기간이 그 달과 겹치거나 그 달 마감 업무가 든 페이즈. 페이즈 없는 업무는 프로젝트마다 「페이즈 없음」 줄로.
페이즈 줄을 누르면 그 업무가 아래에 펼쳐진다(펼친 것은 이 브라우저에 기억).
열: 페이즈·업무(이름 · 프로젝트 · 업무 수) · 담당자(업무 담당자 아바타 묶음) · 타임라인(그 달 안에서의 기간 막대, 페이즈는 진척 채움, 지연은 빨강) · 진행 현황(페이즈는 업무에서 계산한 대기·진행중·지연·완료, 업무는 색 채운 상태 셀렉트 — 바로 바꾼다) · 마감 기한(페이즈 종료일 / 업무 마감, 지연이면 며칠) · 진척률(막대 + % + 완료 수) · 파일(링크·이미지 수).
묶음은 접을 수 있고, 묶음 머리의 「월간 리포트 ›」로 같은 달 리포트로 간다. 좁은 화면은 표가 가로로 스크롤된다.

## 6.6-3 리포트 (전체 대시보드)

이슈·현황 탭을 대신하는 한 장. 입력 칸은 없고 모두 조회 시 계산한다.
- **카드 셋** — 전체 업무(미완료 · 지연 · 미해결 이슈), 미완료 업무 우선순위 분포(높음 · 보통 · 낮음 막대), 전체 진척(실행 p% / 목표 100%).
- **담당자별 진행 상황** — 사람마다 쌓은 막대(완료 · 대기 · 진행중 · 검토 · 지연).
- **마일스톤 일정** — 달력. 마일스톤은 프로젝트 색 알약(달성은 옅게, 지연은 빨강), 그 날 마감인 미완료 업무 수도 선다. ‹ › 로 달 이동.
- **담당자 × 프로젝트** — 자리표. 파랑 = 미완료 n건, 빨강 = 지연 n건, 초록 ✓ = 모두 완료. 누르면 그 사람의 그 프로젝트 업무 목록.
- **전체 프로젝트 일정** — 프로젝트 막대 아래 페이즈 막대(진한 부분이 진척률), ◆ 마일스톤, 오늘 선.
- 머리의 「이슈 n」「월간 리포트」로 각 화면으로 간다.

## 6.7 공통 표시 규칙

| 요소 | 규칙 |
|---|---|
| 날짜 | 당해년도는 `9/8`, 연도가 다르면 `2026. 1. 5` |
| D-Day | `D-2`, `D-DAY`, 지연은 `-3일` (빨간색) |
| 담당자 | 프로필 이미지(20px) + 이름. 비활성은 이름 뒤 `(비활성)` |
| 상태 배지 | 대기 회색 / 진행중 파랑 / 검토 보라 / 완료 초록 |
| 외주 상태 배지 | 동일 색계열 + 외주 아이콘 |
| 지연 | ⚠ + 빨강 |
| 이슈 | 🔥 |
| 진행률 바 | 10칸 블록. 값이 없으면 `-` |
| 프로젝트 색 | 4칸(`--p0`~`--p3`). 프로젝트의 `sort_order` 로 고정 배정. **색 옆에는 늘 이름이 붙는다** |

| 마일스톤 | 마름모. 달성 ✓ 초록 / 지연 ! 빨강 / 예정은 프로젝트 색 테두리 |

| 모바일 (<768px) | 목록을 카드형으로 전환. 업무명·담당·마감·상태만 표시 |

> 모바일은 **조회와 상태 변경**까지만 지원한다. 업무 등록은 데스크톱 우선.
